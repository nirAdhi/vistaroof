Document reader

Which AI reads the documents and answers questions: Ollama (your own server, private), the Claude API (Anthropic) or the Gemini API (Google). Choose the reader and an optional second reader below; each cloud reader needs its own key. The app checks the reader every minute and shows its state here, on the dashboard header and in a notification when it changes.

Claude API (Anthropic)

Get a key at platform.claude.com → API keys. Keys are stored encrypted in the local database and never shown in full again.

Gemini API (Google)

Get a key at aistudio.google.com → Get API key. Gemini reads photos and scanned PDFs like Claude. "Test key" lists the models the key can use.

Company

Used to tell the company's own invoices (money in) from suppliers' invoices (money out).

Changing the name only affects documents read from now on. Use “Full re-read” on a source to apply it to older documents.

Google setup

One-off: the OAuth client that lets this app ask Google for read-only Drive access.

Upload the OAuth client JSON

  1. Go to console.cloud.google.com and create a project (any name).
  2. APIs & Services → Library → enable Google Drive API.
  3. APIs & Services → OAuth consent screen → External → app name + your email → add every Google account you will connect as a test user.
  4. Credentials → Create credentials → OAuth client ID → Desktop app → Download JSON.
  5. Upload that file here.

If you choose a Web application client instead, add as an authorised redirect URI.

Microsoft setup

One-off: the app registration that lets this app ask Microsoft 365 for access to SharePoint and OneDrive files.

Register the app in Microsoft Entra (about 5 minutes)

  1. Go to entra.microsoft.com (or portal.azure.com → Microsoft Entra ID) → App registrations → New registration.
  2. Name: Roofing Ledger. Supported account types: Single tenant when the registration is created in the organisation that owns the files (then put that organisation's domain in the Tenant field below); Accounts in any organizational directory only if several organisations will sign in.
  3. Redirect URI: platform Web, value . Register. Under Authentication you can add a second URI later (for example the local http://127.0.0.1:8000/admin/oauth/ms-callback for testing).
  4. Copy the Application (client) ID from the Overview page into the form below.
  5. Certificates & secrets → New client secret → copy the Value (not the id) into the form. It is shown only once.
  6. API permissions → Add a permission → Microsoft Graph → Delegated: Files.Read.All, Files.ReadWrite.All, Sites.Read.All, User.Read, offline_access. If the organisation requires it, press Grant admin consent.

Guest access. If the files belong to another organisation and were shared with your account (“Specific people → Can view”), add the source with that organisation’s domain in the Organisation (tenant) field, then sign in with your own account. For uploads the share must be “Can edit”.

Data

What this server holds: the extracted figures in data/ledger.db. The documents themselves stay where they are (SharePoint, OneDrive, Google Drive) and are only read, never changed.

Document files on this server

Off (recommended): a preview is fetched from the source every time it is opened and nothing is written to disk. On: the viewable copy is kept under data/previews.

Dates

A document without a date is placed in the dashboard by its file date, which can put an old invoice in the current period. If the reader wrote the date in another notation (14/02/2026, 14 Feb 2026), this recovers it from the stored answer without reading the file again. It also runs by itself at every start.

Demo data

A sample year of a roofing company so the owner dashboard can be explored before anything is connected.

Backup

Download a copy of the database (settings, sources, every extracted document). Keep it somewhere safe; restore by replacing data/ledger.db while the app is stopped.

Download backup

Danger zone

Deletes every extracted document and the sync history. Sources and settings are kept; the next sync re-reads everything (and costs API usage).

Security & users

Everyone who uses the ledger gets their own account (email + password). Users see the dashboard: figures, documents, uploads, questions. Admins also open this area. The built-in admin password stays as a fallback login: its sign-in name is ADMIN_EMAIL from the server environment (with no ADMIN_EMAIL, the email is left empty).

User accounts

Add a user

Tell the person their email and this password; they can change it themselves from the dashboard (Account → Change password).

Admin password (built-in)

The password created on first run. Changing it signs every browser out, including user accounts.

Set by the server environment. ADMIN_PASSWORD (and optionally ADMIN_EMAIL) in .env.production define this login; edit the file and restart the app to change it.
